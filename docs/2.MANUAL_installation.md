# Installation

## Add The Shard

Add CouchBase to `shard.yml`:

```yaml
dependencies:
  couchbase:
    github: shardscry/couchbase
    version: ~> 0.0.5
```

Install dependencies:

```sh
shards install
```

## Connection Strings

Plaintext Couchbase:

```text
couchbase://user:pass@127.0.0.1/commerce
```

TLS Couchbase:

```text
couchbases://user:pass@127.0.0.1:11207/commerce?tls_verify=false
```

Multiple Query or cluster seeds:

```text
couchbase://user:pass@node1,node2,node3/commerce
```

`KV::Client.from_string`, `KV::Pool.from_string`, and
`KV::Cluster.from_string` use `user`, `pass`, and `bucket` from the URI when
they are not passed as arguments.

`Query::Client.from_string` and `Query::Cluster.from_string` use `user`,
`pass`, and the optional bucket path from the URI. Query connection strings do
not include the scope; configure that on calls, on the Query client, or on the
Query cluster.

Supported URI query parameters:

- `tls_verify`: `true`, `false`, `1`, or `0`.
- `tls_hostname`: certificate hostname override.
- `network`: topology alternate address selection for Query clusters.

## Examples

Every directory under `examples/` is a standalone application with its own
manifest, lockfile, local models, and README. Install dependencies inside the
chosen folder before running it:

```sh
cd examples/query_basics
shards install
crystal run example.cr
```

See the [example catalog](../README.md#examples) for KV, SQL++, prepared-query,
streaming, mutation, expiration, and endpoint-discovery examples. CLI examples
accept `COUCHBASE_URL`, `COUCHBASE_SCOPE`, and `COUCHBASE_COLLECTION`; Query
examples also support `COUCHBASE_QUERY_URL` for a separate Query endpoint.

The [Kemal API](../examples/kemal_api/README.md) demonstrates UUID-keyed user CRUD,
SQL++ pagination, and standalone HTTP/integration specs. Its folder also contains
the Docker Compose database setup:

```sh
cd examples/kemal_api
docker compose up -d --wait couchbase
docker compose run --rm couchbase-init
shards install
crystal run setup.cr
crystal run src/main.cr
```

## Development Checks

Run the usual local checks:

```sh
shards install
shards build ameba
bin/ameba
crystal tool format --check --exclude lib --exclude 'examples/*/lib'
crystal build --no-codegen src/couchbase.cr
crystal spec --error-trace
```

Generate API docs:

```sh
crystal docs src/couchbase.cr -o docs --project-version=main-dev --source-refname=main
find docs -type f \( -name '*.html' -o -name '*.css' -o -name '*.js' -o -name '*.json' \) -print0 | xargs -0 perl -pi -e 's/[ \t]+$//'
```

Run real Couchbase integration specs:

```sh
COUCHBASE_INTEGRATION=1 crystal spec spec/integration --error-trace
```

Run TLS integration specs:

```sh
COUCHBASE_INTEGRATION=1 \
COUCHBASE_TLS=true \
COUCHBASE_TLS_VERIFY=false \
COUCHBASE_KV_PORT=11217 \
COUCHBASE_MANAGEMENT_PORT=8097 \
crystal spec spec/integration --error-trace
```

## Local Hooks

Enable local hooks once per clone:

```sh
git config core.hooksPath .githooks
```

The pre-commit hook checks formatting, builds the library, regenerates docs,
and runs specs.

## CI

GitHub Actions runs:

- Driver unit specs, standalone example builds, formatting, and Kemal HTTP specs.
- Kemal API integration specs and CLI example runs against real Couchbase.
- Real Couchbase integration specs against Couchbase Community 7.6 and 8.0.
- Real Couchbase Query TLS integration specs against Couchbase Enterprise 7.6
  and 8.0.
- Real Couchbase Community Query TLS integration specs through an nginx TLS
  reverse proxy.
